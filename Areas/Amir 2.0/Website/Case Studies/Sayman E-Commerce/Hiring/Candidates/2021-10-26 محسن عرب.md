## تخصص لاراول

**middleware ها را در لاراول توضیح دهید.**
middleware ها به عنوان رابط میانی بین ‌درخواست و پاسخ به کار می رود. و برای کارهایی از قبیل تایید هویت و ... به کار می رود.

**چطور می‌تونیم از Validation ها استفاده بکنیم؟**
از تابع validate() که به request متصل (chain) می شود استفاده می کنیم. اگر ورودی ها معتبر نباشند، به آدرس قبلی بر می گردد (redirect). برای کنترل بیشتر در هنگام معتبر نبودن ورودی ها ، از Validator::make() استفاده می کنیم. اگر validation‌ها زیاد باشند، یک Request می سازیم و آنها را در request ساخته شده قرار می دهیم و در پارامتر ارسالی به تابع کنترلر، از آن request ساخته شده استفاده می کنیم.

**رابطه‌های polymorphic رو توضیح بدید.**
one to one : مثلا هر کاربر فقط یک پروفایل دارد و بر عکس.
one to many: هر مدل چندین رابطه دارد. مثلا یک پست دارای چندین کامنت می باشد که در جدول کامنتها باید post_id باشد.
many to many: مثل رابطه پست ها و برچسب ها. هر پست چند برچسب دارد و هر برچسب چند پست دارد . باید یک جدول میانی ساخته شود که آن دو را به هم مربوط کند.

**فرض کنید نام و نام خانوادگی کاربر در دو فیلد جداگانه در دیتابیس ذخیره می‌شود، برای نشان دادن نام نمایشی کاربر که شامل هر دوی این فیلد‌ها هست از چه امکانی می‌توانیم استفاده کنیم؟**
از Accessor ها در لاراول می توانیم استفاده کنیم که هر موقع نام کاربر مورد دستیابی قرار گرفت، نام خانوادگی ان را هم به آن بچسباند.

**Query Scopeها را در مدل‌های Eloquent توضیح بدید**
برای ساخت dynamic query scope و custom query مورد استفاده قرار می گیرند. در مواقعی استفاده می شود که شما یک الگویی را بارها و بارها قرار است که در query های خود مورد استفاده قرار دهید ( نام متد باید با scope شروع شود ).

**در پروژه‌هایی که داشتید با Queue در لاراول کار کردید؟ اگر بله توضیحی درباره نحوه استفاده و مساله‌ای که از صف برای حل اون استفاده کردید بدید**
در مواقعی که قرار است مثلا بعد از ثبت نام کاربر یک ایمیلی به کاربر ارسال شود. اگر از صف استفاده نشود کاربر تا ارسال ایمیل باید در همان صفحه منتظر بماند. اما اگر از صف استفاده کنیم، ثبت نام کابر را به کاربر به عنوان تکمیل شده اعلام می کنیم و آنگاه عمل ارسال ایمیل را در صف قرار می دهیم و آنگاه صف را اجرا می کنیم تا کاربر معطل نماند.

**در مورد Branch و Pull request توضیح بدید.**
برنچ برای مواقعی استفاده می شود که چندین کاربر بر روی پروژه کار می کنند و هر کدامشان روی بخشی از پروژه (روی برنچ خودشان) و Pull request هم برای مواقعی هست که مثلا پروژه ای که داریم روی ان کار می کنیم توسط سایر همکاران به روز شده و در gitlab یا github قرار گرفته و ما می خواهیم ان نسخه بروز شده را روی local خود داشته باشیم.

**بعد از ایجاد هر pull request کدهای شما review میشه و بعد وارد branch اصلی میشه. فکر می‌کنین در مرحله review به چه فاکتورهایی باید توجه بشه؟**
وقتی pull می کنیم باید متوجه conflict ها باشیم که اگر توجه نشود امکان دارد که مثلا دو کاربر روی یک بخش کار کرده باشند و در پروسه merge کدهای انجام شده توسط هر دو نفر کاربر تغییر کند.
