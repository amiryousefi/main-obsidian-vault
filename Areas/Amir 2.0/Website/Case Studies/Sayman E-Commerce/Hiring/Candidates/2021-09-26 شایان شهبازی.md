## تخصص لاراول

**middleware ها را در لاراول توضیح دهید.**
تقریبا مثل firewall ویندوز عمل میکنند و ریکوئست هارو قبل از انجام عملیاتشون بنا به کد هایی ک نوشتیم بررسی و چک میکنند. مثل auth برای چک کردن وضعیت ورود کاربران

**چطور می‌تونیم از Validation ها استفاده بکنیم؟**
بهترین راه استفاده از آن ها اینه که ریکوئست رو قبل رسیدن validate کنیم که میتونیم مثلا یک ریکوئست با نام PostRequest خودمون بسازیم و validate رو توی کلاس خودش انجام بدیم نه توی کنترلر ها

**رابطه‌های polymorphic رو توضیح بدید.**
اگر دو جدول داشته باشیم که هر دو دارای یک ستون مثلا به نام comment باشند ، میتوانیم با استفاده از دستورات morph در دیتابیس و مدل ها رابطه polymorphic ایجاد کنیم

**فرض کنید نام و نام خانوادگی کاربر در دو فیلد جداگانه در دیتابیس ذخیره می‌شود، برای نشان دادن نام نمایشی کاربر که شامل هر دوی این فیلد‌ها هست از چه امکانی می‌توانیم استفاده کنیم؟**
fullName=firstname + lastname

**Query Scopeها را در مدل‌های Eloquent توضیح بدید**
از انها برای دوباره استفاده نکردن query های تکراری استفاده میکنیم

**در پروژه‌هایی که داشتید با Queue در لاراول کار کردید؟ اگر بله توضیحی درباره نحوه استفاده و مساله‌ای که از صف برای حل اون استفاده کردید بدید**
برای ارسال ایمیل از آن استفاده کردم ، ایمیل ها در یک جدول در صف قرار میگرفتند و با شروع صف به نوبت ارسال میشدند

**کاربرد Resource Collectionsها در لاراول چی هست؟**
نحوه نمایش و اطلاعات قابل نمایش در api را میتوان با استفاده از آن ها تغییر داد.

**با تست‌ها در لاراول آشنا هستید؟ چه نوع تست‌هایی در لاراول داریم؟ برای اجرای تست‌ها از چه دستوری استفاده می‌کنیم؟**
خیر ، تست انجام نداده ام

**متد actingAs در تست‌ها به چه منظوری استفاده میشه؟**

## گیت

**بیشتر از چه ابزاری برای بهره بردن از git استفاده می‌کنید؟**
ابزارهای خود IDE مثل PHPStorm یا ..., ترمینال

**فرض کنین قابلیت جدیدی برای امکان اضافه کردن تصویر به دسته‌بندی‌ها رو اضافه کردید. پیغام مناسب برای commit کردن کدهای این قابلیت رو بنویسید.**
PictureForCategory

**در یک repository اگه بخواهیم n کامیت به عقب برگردیم بدون اینکه تغییراتمون در لوکال از بین برن از چه دستوری می‌تونیم استفاده کنیم؟**
Git checkout Head-n

**در مورد Branch و Pull request توضیح بدید.**
وقتی چند نفر قراره روی یک پروژه کار کنند بهتره که هرکس یا هر فیلد یک branch جدا داشته باشند تا کار ها باهم و مخصوصا با مستر قاطی نشوند. از pull هم برای دریافت فایل ها و کدهای یک branch استفاده میکنیم ، یا از merge استفاده میکنیم

**بعد از ایجاد هر pull request کدهای شما review میشه و بعد وارد branch اصلی میشه. فکر می‌کنین در مرحله review به چه فاکتورهایی باید توجه بشه؟**
در مرحله ی اول نبود conflict بین دو branch ، و همچنین تمیز بودن و خوانا بودن کد ها
