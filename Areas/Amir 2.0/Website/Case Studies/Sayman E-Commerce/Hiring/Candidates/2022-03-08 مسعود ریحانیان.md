## تخصص لاراول

**middleware ها را در لاراول توضیح دهید.**
middleware به عنوان لایه های بین درخواست و برنامه عمل می کند. و میتواند از ان برای فیلتر درخواست های HTTP ورودی استفاده کرد. مثلا چک کرد که کاربر لاگین هست یا نه و یا دسترسی لازم به این بحش را دارد یا نه. یا اینکه اگر مثلا چک کرد کاربر سن کابر از محدوده مجاز بالاتر است یا نه و در عیر این صورت خطای مناسب بازگردانده شود و یا redirect شود.

**چطور می‌تونیم از Validation ها استفاده بکنیم؟**
می توان از facade مربوط به validation مستقیما در controller استفاده نمود ولی بهتر است برای این کار کلاس جداگانه با دستو php artisan make:request ساخت و تمامی rules مربوطه را در آن نوشت. و در کنترلر با typehint این کلاس لاراول validation های این کلاس را اعمال خواهد نمود.

**رابطه‌های polymorphic رو توضیح بدید.**
روابطی است یک مدل خاص همزمان میتواند متعلق به چندین مدل باشد. مثلا مدل tag میتواند هم به محصولات و هم به پست های وبلاگ assign شود. که میتواند به صورت روابط چند به چند یا یک به چند باشد. در روابط چند به چند یک جدول میانی مثلا با عنوان taggables مورد نیاز است.

**فرض کنید نام و نام خانوادگی کاربر در دو فیلد جداگانه در دیتابیس ذخیره می‌شود، برای نشان دادن نام نمایشی کاربر که شامل هر دوی این فیلد‌ها هست از چه امکانی می‌توانیم استفاده کنیم؟**
میتوان از accessor در لاراول استفاده نمود با عنوان getFullNameAttribute

**Query Scopeها را در مدل‌های Eloquent توضیح بدید**
اگر یک شرط در query مربوط به یک مدل زیاد استفاده می گردد. می توان آن را به صورت query Scope داخل مدل تعریف کرد مثلا برای فیلتر کردن در مدل تابع با عنوان scopeFilter تعریف کرد و میتوان همه جا با نوشتن مثلا Post::filter($request->query)::get() مدل را فیلتر کرد. global scope هم کلاس جداگانه ای است که در بوت مدل می توان قرارد و همه جا اعمال می شود soft delete لاراول نوعی global scope است.

**در پروژه‌هایی که داشتید با Queue در لاراول کار کردید؟ اگر بله توضیحی درباره نحوه استفاده و مساله‌ای که از صف برای حل اون استفاده کردید بدید**
بله. مثلا برای ایندکس محصولات در الاستیک از queue استفاده می گردد. یا برای import کردن محوصلات از طریق اکسل، بعد از آپلود محصولات در صف ساخته می شود. یا برای ارسال sms یا ایمیل باید از صف استفاده کرد.

**کاربرد Resource Collectionsها در لاراول چی هست؟**
در اپلیکیشن های مبتنی بر api برای این که کنترل کاملی بر خروجی api وجود داشته از api resource استفاده می شود. در api های ایندکس برای کنترل بیشتر بر داده ها مثلا ارسال meta data میتوان از resource collection استفاده کرد.

**با تست‌ها در لاراول آشنا هستید؟ چه نوع تست‌هایی در لاراول داریم؟ برای اجرای تست‌ها از چه دستوری استفاده می‌کنیم؟**
بله. unit test, feature test, integration test
php artisan test یا vendor/bin/phpunit

**متد actingAs در تست‌ها به چه منظوری استفاده میشه؟**
برای authenticate کردن کاربر برای route هایی که دارای middleware auth هستند

## گیت

added pictures to categories

**در یک repository اگه بخواهیم n کامیت به عقب برگردیم بدون اینکه تغییراتمون در لوکال از بین برن از چه دستوری می‌تونیم استفاده کنیم؟**
git reset HEAD~n

**در مورد Branch و Pull request توضیح بدید.**
به عنوان یک git flow استاندارد باید دو برنچ master و develop داشته باشم مستقیما نباید به این دو برنچ پوش کرد. برای افزودن فیچر باید برنچ فیچر ساحته شود که بعد از pull request با برنچ develop مرج میشود. برنچ bugfix نیز برای رفع باگ وبا برنچ Develop مرج می شود. برنچ hotfix برای رفع باگ حیاتی از master گرفته می شود و پس از مرج با master با develop مرج می شود. موقع release برنچ develop با برنچ master مرج می شود.

**بعد از ایجاد هر pull request کدهای شما review میشه و بعد وارد branch اصلی میشه. فکر می‌کنین در مرحله review به چه فاکتورهایی باید توجه بشه؟**
ابتدا باید بررسی گردد که feature درخواستی به درستی پیاده شده است. تست های نوشته شده جامع و کامل است. از نظر کارایی کد چک شود مثلا query اضافه نداشته باشد رابطه ها eager load شده باشد. استاندارهای کد نویسی مورد نظر مثلا نحوه نوشتتن متغیرها و تابع ها ، doc block نوشته شده باشد. متغیرها type hint شده باشد و ... البته برخی از این ها به صورت اتومات نیز قابل انجام است.
